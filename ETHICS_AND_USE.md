# Ethics, Attribution, and Usage Scope

## Scope

- This project is intended for non-commercial project context, including portfolio and research demonstration.
- Any third-party character/image asset must be traceable and attributed.

## Attribution Rules

- Do not present externally sourced visual assets as original team output.
- Keep a written provenance record for every visual shown in project demos.
- If provenance is incomplete, add an explicit "source pending verification" label in slides/demo notes.

## Copyright and License Rules

- Follow upstream license/usage terms for Storyworld and related datasets.
- Do not use unlicensed third-party IP, logos, or copyrighted character world references in public demo materials.
- No commercial use unless explicit permission/license is documented.
- Uploading content to GitHub does not by itself waive attribution or license obligations.
- When original creator identity is unavailable, provide role-ID-level reference to upstream source and clearly state this limitation.

## AI-Generated Content Disclosure

- If an image/audio/text is AI-generated, document model/provider and whether prompts included third-party references.
- Mark generated assets as generated; do not label them as hand-authored originals.

## Runtime Practice

- This repository currently keeps existing visual assets for project demo continuity.
- Compliance is handled by documentation and attribution (`ASSET_ATTRIBUTION.md`) rather than deleting assets.
- Any future filtering/locking should be a team decision before release.

## Team Process

- Before each project showcase, complete `ASSET_ATTRIBUTION.md` checklist.
- Keep evidence links (source URL, author, license statement) with each role asset.
- For AI-randomized role pools, treat every role ID shown in final output as in-scope for attribution.
- For Storyboard-linked roles (`xxxxg`), prefer dual-source references: GitHub character YAML + Hugging Face character image dataset.
