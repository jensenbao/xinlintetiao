# DOC 文档索引与维护规范

本目录只在根层维护少量“当前有效”的主文档。历史方案、阶段性汇总和已经被后续实现覆盖的内容统一放入 `archive/`；对比研究和外部项目分析统一放入 `research/`。

## 当前有效文档

1. [当前状态与已完成.md](当前状态与已完成.md)
   - 当前真实运行架构、已完成功能、停用功能、验证状态和已知缺口。
   - 回答“项目现在实际上是什么”。
2. [开发计划与路线图.md](开发计划与路线图.md)
   - 已排定但尚未全部实现的工作、优先级、验收标准。
   - 回答“接下来准备做什么”。
3. [待商讨与决策.md](待商讨与决策.md)
   - 尚未形成统一决定、会明显影响范围或架构的事项。
   - 回答“哪些事情需要先做决定”。
4. [运行配置与资产维护.md](运行配置与资产维护.md)
   - 启动、网络配置、模型生图、素材同步、路径检查和安全规则。
   - 回答“如何安全运行与维护项目”。

补充资料：

- `research/`：竞品、参考项目和专项技术分析，不作为当前实现承诺。
- `archive/`：历史快照，只用于追溯，不作为当前状态依据。
- `pdf-github-like.css`：Process Book PDF 导出脚本使用的样式资源，不是项目状态文档。

## 状态术语

- **已完成并生效**：代码已进入当前运行路径，静态证据明确，且至少完成构建、路径检查或针对性验证之一。
- **已完成但停用**：代码仍保留，但被功能开关、路由或入口明确关闭。
- **部分完成**：已有一部分链路，但缺少验收、测试、接线或完整闭环。
- **计划中**：已经确定方向和验收标准，尚未全部实现。
- **待商讨**：尚未做出产品或架构决策，不应写成开发承诺。
- **历史记录**：只描述某一时间点，后续可能已经被覆盖。

## 维护规则

1. 功能合入后，优先更新 `当前状态与已完成.md`，不要再创建新的“已完成项汇总-日期.md”。
2. 新计划写入 `开发计划与路线图.md`，完成后移动到“已完成并生效”，而不是在文件末尾重复追加新版本状态。
3. 会改变玩法范围、运行服务或核心数据结构的事项，先写入 `待商讨与决策.md`。
4. 网络、密钥、素材目录和模型生图配置只维护在 `运行配置与资产维护.md`。
5. 主文档描述必须以当前源码和真实命令为准；历史计划不能覆盖当前事实。
6. 当前文档不保存真实 API Key、个人凭证或未公开服务地址。
7. 模型、接口和外部依赖发生变化时，同时更新 `.env.example`、README 与运行维护文档。
8. 每次发布或重要演示前至少核对：

   ```bash
   npm run check:paths
   npm run build
   ```

9. 对无法自动验证的体验指标，明确标记“未验证”，不要写成“已完成”。

## 归档规则

- 归档目录按时间或主题组织，例如 `archive/2026-04/`。
- 归档文档不再继续追加“当前状态”。
- 若历史内容与当前主文档冲突，以主文档和源码为准。
- 删除已经明确放弃且会误导后续开发的完整工作流方案；有价值的背景结论应先提炼进主文档。
