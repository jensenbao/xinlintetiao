# 运行配置与资产维护

> 最近更新：2026-08-29  
> 范围：本地启动、网络配置、API Key、本地角色库、模型生图、素材目录与验证命令。

## 1. 环境要求

- Node.js 18+
- npm 9+
- 本地预览或 PDF 导出所需的 Chrome/Chromium 依赖按脚本要求安装

安装依赖：

```bash
npm install
```

## 2. 本地启动

同时启动前端和本地服务：

```bash
npm run dev
```

分别启动：

```bash
npm run dev:client
npm run dev:server
```

默认地址：

- Vite：`http://localhost:5173`
- 本地服务：`http://127.0.0.1:3001`
- 健康检查：`GET http://127.0.0.1:3001/health`

## 3. API Key 与安全规则

1. 从 `.env.example` 复制或生成 `.env.local`。
2. 真实 Key 只保存在本机 `.env.local`，不得写入 DOC、README、源码或提交记录。
3. 历史上曾暴露的 Key 应立即作废并轮换。
4. 演示前检查终端、截图和录屏中是否出现 Key。
5. API 不可用时显示明确错误，不返回伪造的正式游戏结果。

主要变量：

- `VITE_AI_PROVIDER`
- `VITE_GEMINI_API_KEY`
- `VITE_GEMINI_MODEL`
- `VITE_GEMINI_ENDPOINT`
- `VITE_DEEPSEEK_API_KEY`
- `VITE_DEEPSEEK_MODEL`
- `VITE_DEEPSEEK_ENDPOINT`
- `VITE_OPENROUTER_API_KEY`
- `VITE_ENABLE_REMOTE_TTS`
- `VITE_REMOTE_TTS_ENDPOINT`

## 4. 中国大陆/香港网络配置

可能访问的外部服务包括：

- 模型 API 端点。
- 远程 TTS。

CN/HK 稳定配置：

```bash
npm run env:cnhk
```

该配置默认：

- 优先 DeepSeek。
- 关闭远程 TTS。
- 保留已有 Key 值。

```bash

```

切换命令会重写 `.env.local`。执行后应人工检查 provider、endpoint 和 Key 是否符合当前环境。

## 5. 本地角色库与角色目录

角色数据目录：

```text
seeds/characters/
├─ defaults.json
├─ presets/<readable-slug>/
│  ├─ character.json
│  ├─ source.yaml
│  └─ portrait.*
└─ custom/<readable-slug>/
   ├─ character.json
   ├─ source.yaml
   └─ portrait.*
```

规则：

- 每个 NPC 只使用一份 `character.json` 作为运行时主清单。
- `defaults.json` 单独登记默认加载的预置角色 slug。
- `source.yaml` 是原始设定来源和归档依据。
- 目录使用可读 slug；稳定内部 ID 保留在清单中以兼容存档。
- 禁止通过角色 ID 构造路径穿越。
- 新角色必须先以完整本地目录写入 `custom/`，不要覆盖 `presets/`。
- 运行时只索引 `presets/` 和 `custom/` 下的 `character.json`。
- 运行时不连接外部角色仓库或肖像数据集；缺少本地资料或肖像时直接返回明确错误。
- 当前预置角色为 `captain-quick` 与 `aquabyte-98`；两者都必须在 `defaults.json` 中显式登记才会进入默认角色池。
- 删除 NPC 时必须同步处理角色目录、`defaults.json`、前端预置清单导入、舞台 cutout 绑定、`public/asset/角色/cutout/` 和 `ASSET_ATTRIBUTION.md`。
- 浏览器旧存储可能暂时保留已删除角色 ID；重新进入 New Game 并完成本地角色扫描后，角色池会按现有本地清单重写。
- 调整目录结构后运行：

  ```bash
  npm run migrate:characters
  ```

### 5.1 `character.json` 统一清单

每个 NPC 的清单使用相同职责划分：

- `schemaVersion`：清单格式版本。
- `id`：兼容存档和缓存的稳定内部 ID，不用于界面显示。
- `slug`：可读目录名和资产包名称。
- `displayName`：玩家可见名称。
- `kind` / `preset`：区分预置与自定义角色。
- `lockedUntilUserAdded`：默认角色池约束。
- `character`：profile、background、dialogueStyle、voiceProfile、gender 等运行时角色信息。
- `assets`：source、portrait、concept、pixel、generation 和 publicCutout 的相对路径。
- `emotionSchemaVersion`、`currentEmotionWeights`、`currentEmotionTop3`、`emotionAnalysis`：角色初始情绪资料。

当前有效资产：

```text
presets/captain-quick/character.json
presets/aquabyte-98/character.json
custom/  # 当前无自定义角色
```

`defaults.json` 当前登记 `captain-quick` 与 `aquabyte-98`。仅把目录放进 `presets/` 不会自动加入游戏默认池。

## 6. 模型生图

后续角色图像统一使用模型生图 API，不维护独立的节点工作流或任务轮询协议。

当前入口：

- 服务端：`server/character-image-service.mjs`
- HTTP 路由：`/api/mcp/character/generate_images`
- 前端调用：`src/utils/localCharacterRepository.js`

主要配置：

- `VITE_CHARACTER_IMAGE_MODEL`
- `VITE_CHARACTER_IMAGE_ENDPOINT`
- `VITE_OPENROUTER_API_KEY` 或对应兼容服务 Key

推荐流程：

```text
读取 `character.json`
  → 生成角色提示词
  → 服务端调用图像模型
  → 校验响应格式和图片大小
  → 必要时执行去白底/裁切
  → 写入对应角色目录
  → 使旧缓存失效
  → 前端重新加载
```

维护原则：

- 生图失败时保留已有头像或使用明确占位图，不阻断核心游戏。
- 不在前端暴露服务端专用 Key。
- 保存模型名、提示词版本、生成时间和来源说明。
- 替换已有资产前保留可恢复版本或要求人工确认。
- 演示使用的生成素材同步登记到 `ASSET_ATTRIBUTION.md`。

相关命令：

```bash
npm run image:remove-white-bg
```

## 7. 美术素材目录与同步

### 7.1 权威来源

```text
Art-assets/Art assets/...
```

团队新素材先放在该目录。

### 7.2 运行时目录

```text
public/asset/...
```

运行时 URL 如 `/asset/角色/...` 从这里提供。不要直接手工维护重复副本。

### 7.3 同步流程

```bash
npm run assets:sync
npm run check:paths
npm run build
```

同步脚本会处理部分历史路径兼容，并清理不再由源目录产生的生成文件。

安全规则：

- 不随意移动或重命名 `public/asset/` 文件。
- 不随意移动或重命名 `Art-assets/Art assets/` 文件。
- 必须保持角色 ID 在 seeds、立绘、cutout 和 attribution 中一致。
- 优先新增文件和更新引用，避免大范围原地改名。
- 概念稿等非运行时资料不必同步到 `public/asset/`。

2026-08-29 最新一轮角色库修改按用户要求未执行以下验证；该清单保留供人工检查。

1. `npm run check:paths` 通过。
2. `npm run build` 通过。
3. `/health` 可访问。
4. 本地角色可以加载。
5. Captain Quick 与 Aquabyte-98 的本地 character manifest、source、portrait 与 cutout 均可正常加载。
6. 对话可正常返回。
7. 关闭 TTS 后不影响核心玩法。
8. 模型生图失败时不覆盖有效旧图，也不阻断新游戏。
9. `.env.local` 没有被 Git 跟踪。
